# Олимпикс — пошаговый план разработки

## Стек

| Слой | Выбор | Почему |
|---|---|---|
| Интерфейс | **React 18 + TypeScript + Vite** | Много интерактивных экранов (уроки, карточки, карта модулей). Чистому HTML/JS это быстро перерастает. TypeScript ловит ошибки в модели данных урока ещё до запуска. |
| Стили | Свой CSS с токенами (`app/src/styles.css`) | Полный контроль над фирменной палитрой из логотипа и без лишних зависимостей. |
| Состояние | Zustand (сохраняется в localStorage) | Это этап 1, сайт работает без сервера. Формы данных совпадают с будущими таблицами. |
| PDF | react-pdf (pdf.js) | Листание, масштаб, оглавление из самого PDF, выделение текста. |
| Аккаунты и БД (этап 2) | **Supabase**: Postgres + Auth + Storage + RLS | Вход по e-mail, роли (ученик / редактор / админ), хранение PDF, защита данных на уровне строк. Есть бесплатный тариф. |
| ИИ (этап 3) | Claude API через серверную функцию (Supabase Edge Function) | Ключ API никогда не попадает в браузер. Ответы опираются на текст выбранной главы. |
| Хостинг | Vercel или Netlify (фронтенд) + Supabase | Деплой одной командой, HTTPS, бесплатно на старте. |

## Этап 1 — Работающий прототип без сервера ✅ (сделано)

- [x] Фирменный стиль: палитра логотипа, шрифты Unbounded / Inter / JetBrains Mono, водяной знак «ОЛИМПИКС» на всех экранах, адаптивность (боковое меню на компьютере, нижняя панель на телефоне).
- [x] Вход по имени или псевдониму (пока локально).
- [x] **Главная:** приветствие, две равноправные карточки путей, повторение на сегодня, слабые темы, последние результаты.
- [x] **Обучение:** карта курса (10 модулей из `prompt.pdf`), карта модуля 1 из 30 уроков (повторения на 5/10/15/20/25/30), последовательное открытие уроков.
- [x] **Урок:** вводная практика → теория → практика → резюме → финальная проверка → результат. Уроки 1 и 2 полностью готовы. Типы заданий: выбор одного или нескольких ответов, пропущенное слово, верно/неверно, соединение пар, открытый ответ со сверкой с эталоном.
- [x] **Анализ ошибок:**
  - каждая ошибка связана с понятием и навыком;
  - система определяет вероятную причину и помечает её «предположительно», пока причина не повторится дважды;
  - ученика спрашивают «почему ты так ответил(а)?»;
  - есть кнопка «Объясни проще» и похожее задание для закрепления;
  - ошибка возвращает связанные карточки в повторение.
- [x] **Зоны роста:** слабые понятия, навыки, динамика по неделям, рекомендация, адаптивная тренировка по личному плану (смешанное повторение только когда слабых тем или заданий по ним не хватает).
- [x] **Повторение:** наборы по модулям, 6 режимов, переворот карточки, оценка «Не знаю / Трудно / Знаю / Легко», интервалы день → 3 → 5 → 7 дней → дальше по персональному коэффициенту.
- [x] **Библиотека:** каталог с поиском, PDF-просмотрщик (страницы, масштаб, переход, полный экран, закладки, последняя страница, главы из оглавления PDF). Подробный конспект с оглавлением и поиском. Режим «учебник + конспект» синхронизирован по главам.
- [x] **Мой прогресс:** XP, уровни, серия дней (пропуск не наказывается), активность, достижения.
- [x] **Олимпиады:** умный список (регистрация, этапы, даты, льготы) и режим «до дедлайна» с расчётом темпа.
- [x] Удаление всех данных из профиля.
- [x] Вкладки и урок запоминают место: шаг урока, начатый ответ, страница, масштаб, прокрутка.
- [x] Выделение цветом и заметки в PDF (хранятся в браузере; перенос в аккаунт — на этапе 2).
- [x] Карточки: свободное листание вперёд и назад, переворот в обе стороны, оценка по желанию.
- [x] Зоны роста: персональный план по этапам, собственные ошибки ученика, новый подбор после каждой тренировки.

## Этап 2 — Аккаунты, база данных, админка

1. Создать проект Supabase и описать схему из мастер-промта (§15). Таблицы: `subjects`, `courses`, `modules`, `lessons`, `theory_blocks`, `concepts`, `questions`, `question_sources`, `answer_options`, `user_attempts`, `error_categories`, `user_weaknesses`, `user_mastery`, `flashcards`, `decks`, `review_schedules`, `textbooks`, `chapters`, `page_references`, `bookmarks`, `user_progress`, `achievements`, `legal_sources`, `content_review_history`. Формы уже заданы в `app/src/domain/types.ts`.
2. Перенести контент из `app/src/content/*.ts` в таблицы скриптом-сидом.
3. Включить Supabase Auth (e-mail + magic link) и роли `student` / `editor` / `admin`. Политики RLS: ученик видит только свои данные, контент меняет только редактор.
4. Заменить `useStore` на слой репозиториев (тот же интерфейс, другой источник данных). Добавить кнопку «перенести локальный прогресс в аккаунт».
5. Сделать админ-панель `/admin`:
   - предметы, модули и уроки с редактором теории и заданий и предпросмотром;
   - карточки;
   - загрузка PDF и конспектов в Storage;
   - статусы контента: Черновик → Создано ИИ → На проверке → Проверено редактором → Опубликовано → Архивировано;
   - для реальных олимпиадных заданий — обязательные поля источника (олимпиада, год, этап, ссылка), без них публикация невозможна.
6. Добавить в редакторе поля правового контента: юрисдикция, отрасль, нормативный источник, статья, дата редакции, пометка «неактуально».

## Этап 3 — ИИ-функции

1. Edge Function `ai` с отдельными режимами, у каждого свой системный промт:
   - Lesson Assistant;
   - Error Analyzer;
   - Adaptive Practice;
   - Flashcard Generator;
   - Tutor;
   - Olympiad Task Generator.
2. Тьютор отвечает только по тексту выбранной главы. В ответе он указывает страницу или раздел, а если ответа в тексте нет — прямо говорит об этом.
3. Анализ ошибок: модель получает задание, выбранный вариант, проверяемые понятия, историю ученика и его объяснение «почему». Возвращает причину и уверенность. Правило «предположительно, пока не подтвердится» сохраняется.
4. Кнопки «Создать карточки по главе» (с предпросмотром перед добавлением) и «Проверь меня по главе».
5. Всё, что сгенерировано ИИ для основного курса, попадает в админку со статусом «Создано ИИ». Ученику такие задания показываются только с плашкой «Авторское задание, созданное ИИ».
